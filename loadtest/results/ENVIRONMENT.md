# Test environment

**Every number in this suite is "local, single machine".** The load generator (k6), the app,
Postgres and Redis all ran on one laptop and competed for the same 8 cores and 8 GB of RAM.
Traffic went from k6 on macOS through Docker Desktop's port forwarding into a Linux VM. The numbers
describe this setup only. They are not production capacity figures.

## Env vars changed for the test

Set through [../docker-compose.loadtest.yml](../docker-compose.loadtest.yml); everything else is the base `docker-compose.yml` default.

| variable | value in measured runs | code default | note |
|---|---|---|---|
| `API_RATE_LIMIT_REQUESTS` | 10000000 | 100 | **raised**; L8 uses 100 |
| `API_RATE_LIMIT_WINDOW` | 1m | 1m | not forwarded by the base compose file, so the override adds it |
| `AUTH_RATE_LIMIT_REQUESTS` | 10000000 | 10 | **raised**; L8 uses 10 |
| `AUTH_RATE_LIMIT_WINDOW` | 1m | 1m | as above |
| `LOG_LEVEL` | warn | info | L8 and L9 use `info` (they need the startup and shutdown log lines) |
| `JWT_SECRET`, `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD`, `BOOTSTRAP_ADMIN_NAME`, `POSTGRES_PASSWORD` | generated per checkout into `loadtest/.state/` (gitignored) | none or compose default | required to start; throwaway |

Isolation-only changes, with no effect on app behaviour: compose project `lottery-loadtest`; container names
`lt_app`, `lt_postgres` and `lt_redis`; Postgres and Redis ports not published; app published on `127.0.0.1:18080`.

Not changed: `LOCK_TTL` (5 s), pool sizes (pgx 25, Redis 20), HTTP timeouts, `JWT_EXPIRY` (24 h), bcrypt cost (12).
